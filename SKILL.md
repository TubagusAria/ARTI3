# ARTI3: Autonomous Rigorous Team & Impeccable Implementation Infrastructure

**ARTI3** synthesizes collaborative multi-perspective design, high-velocity parallel agent orchestration, uncompromising UI/UX craft floors, and pre-action verification gates into a single end-to-end engineering system.

---

## ⚡ When to Activate ARTI3

- Starting a new product, complex feature, full-stack service, or redesign from the ground up.
- Requiring multi-role validation (Product, Architecture, Dev, QA, Design) before a single line of code is written.
- Tasks requiring **maximum throughput** (parallel agent execution) without sacrificing correctness or introducing bugs.
- Building user interfaces that must reject bland, default AI designs in favor of fluid, tactile, accessible, and bold experiences.
- Complex agent delegation where agents must not prematurely self-certify poor work.

## Detailed Execution Guidelines

### Phase 1: 5-Lens Team Discovery & Deep Interrogation Protocol
Extract the core problem statement into a clean 1-paragraph brief, then run analysis across all 5 personas (Maya, Viktor, Kai, Elena, Soren) in parallel.

#### 🎯 The High-Leverage Interrogation Mandate (Kencengin Pertanyaan)
**NEVER GUESS OR ASSUME UNSTATED REQUIREMENTS.**
The user specifically operates at peak performance when thoroughly questioned. Rushing to code with ambiguous assumptions is considered an immediate failure mode. Before finalizing requirements or writing code, ARTI3 and the squad must relentlessly probe and clarify:

1. **Maya (PM — Scope & User Truth):**
   - *"Siapa target spesifik yang bakal frustrasi kalau fitur ini tidak ada?"*
   - *"Batas garis tegas MVP v1 di mana? Apa yang secara sadar kita potong/tunda ke v2?"*
   - *"Bagaimana alur pengguna (happy path vs edge path) saat pertama kali masuk?"*

2. **Viktor (Architect — Invariants & Scalability):**
   - *"Berapa estimasi volume data & concurrency? Perlu offline-first atau real-time sync?"*
   - *"Di mana single source of truth untuk state, dan apa boundary kegagalannya?"*
   - *"Apakah ada batasan infrastruktur, latensi (<100ms), atau dependensi eksternal yang sensitif?"*

3. **Kai (Dev — Stack & Ergonomics):**
   - *"Ada preferensi framework, package versions, atau styling system tertentu?"*
   - *"Bagaimana struktur folder/arsitektur yang sudah ada di codebase yang wajib ditaati?"*
   - *"Perlu TypeScript tipe ketat (strict mode), Zod validation, atau runtime contract khusus?"*

4. **Elena (QA — Failure Modes & Testing):**
   - *"Kondisi apa saja yang dianggap kegagalan fatal (crash, data corruption, silent error)?"*
   - *"Bagaimana penanganan saat network putus, timeout, atau user menginput data sampah?"*
   - *"Apa acceptance test objektif yang bisa dijalankan untuk membuktikan fitur ini lolos 100%?"*

5. **Soren (Design — Aesthetic Direction & Taste Dials):**
   - *"Referensi produk apa yang ingin disamai atau dilampaui feel-nya (Linear, Vercel, Stripe, Raycast, editorial magazine)?"*
   - *"Berapa target angka untuk 3 Taste Dials: Variance (1-10), Motion (1-10), Density (1-10)?"*
   - *"Apakah interface harus mendukung Dark/Light mode otomatis, high contrast, atau fixed theme?"*

#### 🔘 Mandatory Interactive UI Protocol: `ask_question`
**DO NOT ASK OPEN-ENDED WALL-OF-TEXT QUESTIONS.**
The user specifically prefers interactive, clickable multiple-choice options that render directly as selection bars above the chat prompt bar.

ARTI3 must strictly translate the squad's questions into the native `ask_question` tool:
- **Clickable Options:** Provide 3–5 concrete, well-scoped options for each dilemma so the user can answer with a single click.
- **Recommended Option First:** Always place the squad's recommended path as the first choice, prefixed with `(Recommended)`.
- **Multi-Select when Applicable:** Set `is_multi_select: true` for decisions that aren't mutually exclusive (e.g. devices supported, feature inclusions, tech integrations).
- **Batched Interrogation Round:** Present 2–4 targeted questions in a single `ask_question` call covering:
  1. *Scope & MVP Boundary* (Maya)
  2. *Architecture & Tech Stack Choice* (Viktor/Kai)
  3. *UI Taste Dial & Aesthetic Reference* (Soren)
  4. *Failure Tolerance & Edge Verification* (Elena)

Only after the user selects their choices from the interactive prompt bar does ARTI3 synthesize the decisions and proceed to Phase 2 & 3.

### Phase 2: Impeccable Craft Floor, Taste Dials & 21st.dev Component Engineering
Never settle for generic AI templates, centered purple-gradient heroes, or sterile cards. Elevate the interface with deliberate taste and production-grade community primitives.

#### 1. Anti-AI-Slop Manifesto (from Taste Skill — tasteskill.dev)
- **Forbidden Defaults:** Strictly reject the default "AI aesthetic" (Inter font on every element, centered hero with purple/blue mesh background, predictable 3-column icon cards, sterile grayscale borders).
- **Strictly Ban AI Pill/Capsule Bubbles:** NEVER use floating pill/capsule badges above titles or headings (e.g., `[● TALENT PASSPORT...]`, `[✨ Tier 1 • Feature...]`, rounded-full border bubbles with glowing dots or sparkles). This is the #1 dead giveaway of generic AI-generated templates.
  - *Better Alternative:* Use clean, unboxed typographic eyebrows (`text-xs font-semibold tracking-widest uppercase text-muted-foreground`), understated numbering (`01 / PLATFORM`), or let the strong headline carry the hierarchy without decorative pill clutter.
- **Strictly Ban Random UI Emojis (Mandate Lucide Icons):** NEVER decorate titles, greetings, buttons, or badges with cartoon emojis (e.g., `... (Tersertifikasi)! 👋`, `📐 Banner Pop-up...`, `🚀 Get Started`, `💡 Tip`, `🔥 Hot`). Emojis instantly degrade professional authority and scream cheap AI template.
  - *Proper Standard:* Always use clean, sharp vector icons from **Lucide Icons** (`lucide-react`), Radix Icons, or Heroicons. Maintain consistent stroke width (`stroke-[1.5]` or `stroke-2`), optical alignment (`inline-flex items-center gap-2`), and matching semantic color tokens. Let typography and whitespace create hierarchy, not emojis.
- **Curated Assets & Real Visuals:** Use high-contrast editorial typography, authentic open-licensed photography/assets, and intentional whitespace rather than generic placeholder boxes.

#### 2. Configurable Taste Dials (Calibrated per Surface)
When shaping the interface, calibrate and declare these three numeric dials (1–10):
- **`DESIGN_VARIANCE` [1–10]:**
  - `1–3`: Structured, familiar, calm, orthodox SaaS layout.
  - `4–7`: Contemporary product UI, asymmetric accents, distinctive rhythm.
  - `8–10`: Avant-garde, editorial, bold typography, magazine-grade layout.
- **`MOTION_INTENSITY` [1–10]:**
  - `1–3`: Minimal, instant state changes, subtle opacity fades.
  - `4–7`: Fluid spring physics, tactile hover lifts, smooth accordion expansions.
  - `8–10`: Kinetic, magnetic buttons, scroll-driven transforms, interactive canvas.
- **`VISUAL_DENSITY` [1–10]:**
  - `1–3`: Spacious, breathing room, generous whitespace (landing/marketing).
  - `4–7`: Balanced application layout (modern web apps, workflows).
  - `8–10`: Compact, high-information cockpit (trading, monitoring, analytics tables).

#### 3. 21st.dev Component Registry Sourcing
Instead of hand-coding fragile static CSS for complex animations, leverage production-tested community primitives from **21st.dev** ("The npm for Design Engineers") and modern registry ecosystems:
- **Registry Ingestion:** Utilize components from top registries (ibelick, Origin UI, Magic UI, Aceternity UI, Kokonut UI, React Bits) via `npx shadcn@latest add "https://21st.dev/r/[author]/[component]"`.
- **High-Impact UI Blocks:**
  - *Text Effects:* Blur reveal, text stagger, shiny gradients, flipping rotating cyclers.
  - *Interactions:* Magnetic buttons, spotlight hover cards, click spark bursts, dock magnification.
  - *Bento & Grids:* Interactive bento grids with animated luminous borders, tilt cards.
  - *Atmospheric Backdrops:* Shader waves, interactive dot meshes, aurora gradients (applied with restraint).

#### 4. Surface Modes (from Impeccable)
- `Persuade`: Landing, conversion, marketing (visitor acts; bold visuals, distinct typography).
- `Operate`: Dashboards, tools, workflows (visitor completes a task; scanability, tabular nums).
- `Read`: Documentation, content (visitor understands; optical reading rhythm, comfortable line length).
- `Experience`: Portfolios, showcases, games (visitor is inside the work; interface recedes).

#### 5. Tactile Polish (Feel-Better Rules)
- **Concentric Radius:** `outer_radius = inner_radius + padding`.
- **Optical Alignment & Icon Coherence:** Asymmetric icons (play arrows, stars, carets) adjusted with optical offset rather than pure geometric centering. Always use Lucide icons (`lucide-react`) with consistent stroke weight (`stroke-[1.5]` or `stroke-2`) and uniform bounding boxes (`w-4 h-4` / `w-5 h-5`). Never mix emojis with vector icons.
- **Subtle Layered Depth:** Subtle transparent borders + layered shadows over harsh borders.
- **Typography Precision:** `text-wrap: balance` on headings, `text-wrap: pretty` on copy, `font-variant-numeric: tabular-nums` for counters, tables, and monetary figures.
- **State Completeness:** Every screen must account for Loading (skeleton), Error with retry, Empty state with clear CTA, and Focus/Hover/Active states. Minimum touch/click target >= 44px.

### Phase 3: Teamwork Specification & GateGuard Verification

1. **Maintain Live Artifact**: Create and update `prompt_draft.md` across turns.
2. **Specify What, Not How**: Define deliverables (R1, R2, ...) strictly in terms of behavior and constraints. Preserve the implementing agent's solution space.
3. **Objective Verification as Forcing Function**:
   - Every requirement must have an objective verification target (test suite, CLI bot check, or explicit rubric).
   - Prevent premature agent self-certification ("it works on my machine").
4. **GateGuard Fact-Forcing Gate**:
   - Before writing or editing any file:
     1. Search and list all files importing or depending on the target file.
     2. Identify public signatures, types, or schemas affected.
     3. Verify exact schema, date formats, or payload structures.
     4. Proceed only with proven facts, never assumptions.

---

### Phase 4: High-Velocity Parallel Execution

Transform execution into a concurrent dependency graph:

1. **Construct Lane Matrix**:
   | Lane | Parallel? | Write Surface | Risk | Verification |
   |---|---|---|---|---|
   | Discovery / Schema | Yes | None (Read-only) | Low | Glob / Grep / Read |
   | Core / Backend | In-lane | `src/server` | Medium | Unit / Integration Tests |
   | UI / Frontend | Parallel | `src/components` | Medium | Visual review / Lint |
   | QA / E2E Suite | Gated | `tests/` | Low | Test Runner Results |

2. **Batching**: Group independent searches, file inspections, and lint runs into batched calls.
3. **Delegation**: Once the user approves the prompt draft, delegate to `teamwork_preview` or launch parallel subagents with strict isolation.

---

### Phase 5: Bounded Verification & Polished Delivery

1. **Programmatic Verification First**: Run automated test suites and linters. No self-judging.
2. **Bounded Visual Review**: Run inspection once with a batched round (Desktop and Mobile simultaneously).
3. **Single Batch Fix**: Collect all defects found during inspection and resolve them in one cohesive pass.
4. **Deliver Evidence Table**: Close the turn with an objective verification matrix showing pass/fail status per acceptance criterion.
